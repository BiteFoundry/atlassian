CLI `view --json` (`atlassian view`, `atlassian wiki view`, `conf view`) now defaults to compact JSON, matching MCP `get_jira_issue` and `get_confluence_page`. Compact responses include an `omitted` summary of left-out collections and field paths (using `null` when a count is unknown) and a `hint` showing how to retrieve the full payload (on the reference 20-comment issue fixture, compact output is 1,076 B vs 25,834 B full, compared with 324 B in v0.5.1 before `omitted` and `hint`). Scripts that read full fields should add `--full` (for example, `atlassian view ENG-42 --json --full` or `conf view 40211 --json --full`); `--compact` remains accepted as a compatibility alias and HTTP detail endpoints keep full as their default.

Collection listings in the CLI and MCP now include `returned`, `has_more`, and `next_cursor`, and accept `--cursor` / `cursor` to continue reading without silent truncation. Catalog refreshes for projects, boards, and Confluence spaces follow all upstream pages before paging from the local cache (default 50 in JSON/MCP; pass `--limit 1000` / `limit: 1000` and `cursor` when needed), while sprints, board issues, and root or child page listings read one upstream page per call. CLI `issues` and `search --remote|--jql` now emit `next_page_token`, `next_start_at`, and `total` and accept `--page-token` or `--start-at`, and HTTP `GET /issues?offline=true` returns the full cached match count in `total`.

Confluence `has_children` now reports `true`, `false`, or `null` (unknown) based on local cache knowledge without extra upstream requests. Full issue and page detail responses include an `incomplete` array when a subresource fails or is truncated (including partial Jira comment lists), and omit the key when complete. Cached board issues and page lists are pruned only after a complete first page (`has_more == false`).
